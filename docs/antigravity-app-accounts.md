## 二、规则

### 规则 1：区分来源

- 会话来源由数据库所在的目录决定：
  - `antigravity/conversations` 和 `antigravity-ide/conversations` 是客户端，标签为「Antigravity App」。
  - `antigravity-cli/conversations` 是 CLI，标签为「agy」。
- 两者的 `agent` 仍然都是 `antigravity`。额度、套餐、按代理合计都不拆开，只在会话和明细里显示不同的标签。
- 子代理对话跟随它的主对话的来源。
- 数据库已经删掉、只剩账本记录的老会话：账本里记过来源的按记录显示，没记过的标「agy」（与以前的「Antigravity CLI」同义，不猜）。

### 规则 2：客户端的对话不再用 CLI 日志猜账号

- 账号归属里的规则 a、b 只用于 CLI 的对话。
- 客户端的对话一律走规则 3。

### 规则 3：客户端账号按 Kanjo 自己记的「登录记录」归属

1. **记录**：Kanjo 每次扫描（app 后台刷新、`kanjo export`）都读一次 `lastLoginUsername`，规范成小写邮箱，和读取时间一起追加到本地记录里。
   - 记录文件：数据目录下的 `antigravity-app-logins.jsonl`，权限 0600。
   - 只有账号和上次不同，或者距离上次记录超过 1 小时，才追加一行，所以文件很小。
   - 读不到文件、没有这个键或者不是合法邮箱时不记录，也不报错。
2. **归属**：客户端一条消息的时间是 t。
   - 找出 t 之前最近的一条记录 A，和 t 之后最近的一条记录 B。
   - A 和 B 的账号相同，就归给这个账号。
   - t 晚于最后一条记录，并且离它不超过 2 小时（下一次扫描还没到），就归给最后一条的账号。
   - 其他情况一律算「未知」：
     - 两条记录的账号不同。中间切换过账号，不知道在哪一刻切换的。
     - 没有记录。
     - t 早于第一条记录，也就是开始记录之前的历史。
3. **不碰登录凭据**：只读 `app_storage.json` 里这一个键，不读钥匙串、Cookies 或令牌。
4. **隐私不变**：邮箱照旧只出现在完整导出的 `antigravity_accounts` 里。`--mobile`、`--family-report` 和 `--public-summary` 照旧不含邮箱。家庭上报的账号过滤同样适用于客户端的消息：账号未知的客户端消息，在配置了账号过滤时照旧排除。

### 规则 4：非 git 文件夹自成项目

- 工作目录存在、不是 git 仓库、也不在排除列表里时，按文件夹名单独成为一个项目（例如「校招」），不再进入「未归属」。
- 以下情况仍然算「未归属」：
  - 主目录本身；
  - 临时目录（`/tmp`、`/private/tmp`、系统临时目录）；
  - 工具自己的目录（`~/.gemini/…/brain/…/scratch`、`~/.claude` 等）；
  - 已经不存在的目录；
  - 没有工作目录。
- **影响面**：这一条影响所有 agent，不只是 Antigravity，所以单独确认。

## 三、实现要点

- **CLI 解析**：`sources/antigravity.py` 按数据库所在目录设置来源，客户端会话的标签用「Antigravity App」，CLI 用「agy」。`antigravity_accounts.py` 新增客户端登录记录的读写和按时间归属，规则 a、b 只对 CLI 会话生效。
- **缓存**：解析缓存和账号缓存的版本号加一，让已有会话重新归属。账本里的老会话按规则 1 处理来源，账号随重新解析更新。
- **Mac / Windows / iOS / 家庭服务器**：只显示标签，不需要改逻辑。三端对照（parity）的金标数据如果包含标签，就一起重新生成。
- **测试**：
  - 来源标签和子代理跟随主对话。
  - 规则 a、b 不作用于客户端对话。
  - 登录记录的追加、去重和 1 小时间隔。
  - 归属：前后记录相同、切换账号、最后一条之后 2 小时内、早于第一条记录。
  - 读不到或格式不对的 `app_storage.json`。
  - 隐私：精简导出里不含邮箱。
  - 规则 4（如果做）：各种例外目录。
- **真实数据核对**：在复制出来的数据目录里跑。确认客户端对话不再按规则 b 被算到 CLI 账号上；开始记录之后的客户端用量能归到当前账号；「未知账号」和总花费的变化都能解释清楚。
